# 학습 노트


## 학습 상태

- 현재 상태: 풀이를 참고하여 코드 리뷰 중
- 혼자 해결 여부: 해결하지 못함
- 최초 접근: BFS + 트리 DP
- 참고한 접근: DFS 완전탐색 + BFS 감염 확산
- 목표: 코드를 외우는 것이 아니라 각 함수의 역할을 설명할 수 있도록 이해하기

---


## 문제를 처음 읽고 생각한 내용

문제가 트리 구조로 주어졌기 때문에 트리 DP를 먼저 떠올렸다.

감염 시작 노드를 루트로 정한 뒤, BFS를 사용해서 각 노드의 부모와 자식을 구분하려 했다.

그다음 같은 파이프 타입으로 연결된 자식들을 하나의 영역으로 묶고, 각 영역에서 감염시킬 수 있는 최대 노드 수를 DP로 계산하려 했다.

내가 처음 생각한 흐름은 다음과 같았다.
감염 노드를 루트로 설정
    ↓
BFS로 부모와 자식 구분
    ↓
파이프 타입별 영역 생성
    ↓
각 자식 영역을 DP로 계산

---


## 최초 접근에서 막힌 부분

각 서브트리를 독립적으로 계산할 수 있다고 생각했지만, 한 타입의 파이프를 열면 현재 감염된 모든 노드에서 동시에 감염이 퍼진다.

예를 들어 왼쪽 서브트리에서 A 파이프를 열기 위한 선택이 오른쪽의 이미 감염된 영역에도 영향을 줄 수 있다.

또한 다음과 같이 같은 타입을 다시 여는 경우도 있다.
A → B → A

첫 번째 A에서 감염되지 못했던 영역이 B를 통해 감염된 후, 두 번째 A에서 추가로 감염될 수 있다.

이 때문에 단순히 각 서브트리의 결과를 더하는 방식으로는 계산하기 어려웠다.

다음과 같은 DP 상태를 만들려고 했지만 명확하게 정의하지 못했다.
dp[노드][남은 행동 횟수]

이 상태만으로는 현재 어떤 노드들이 감염되었는지 알 수 없다.
dp[노드][남은 행동 횟수][마지막 타입]

으로 확장해도 다른 영역의 감염 상태를 표현하기 어렵다.

---


## 참고 풀이에서 새롭게 알게 된 점

### 1. 이 문제에서 선택하는 것은 노드가 아니다

처음에는 트리의 어떤 방향으로 이동할지를 선택한다고 생각했다.

하지만 실제 행동은 다음 세 가지 중 하나다.
A 타입 열기
B 타입 열기
C 타입 열기

즉, 탐색해야 하는 대상은 노드의 경로가 아니라 파이프 타입의 순서이다.

---

### 2. k가 작다는 점이 중요하다

`k`가 최대 10이라면 파이프 선택 순서를 전부 확인할 수 있다.

아직 완전히 익숙하지는 않지만, 제한을 보고 완전탐색 가능성을 먼저 확인해야 한다는 점을 알게 되었다.

---

### 3. DFS와 BFS의 역할이 다르다

현재 이해한 역할은 다음과 같다.
DFS:
어떤 타입을 어떤 순서로 열지 결정

BFS:
하나의 타입을 열었을 때 감염이 어디까지 퍼지는지 계산
DFS가 감염을 직접 퍼뜨리는 것은 아니다.

BFS가 최적의 순서를 선택하는 것도 아니다.

두 알고리즘이 서로 다른 역할을 담당한다.

---


## 아직 이해하지 못한 부분

### 1. DFS의 분기 구조

다음 반복문이 A, B, C 선택을 만든다는 것은 알고 있다.
for selected_type in range(1, 4):

하지만 재귀 호출이 실제로 다음 순서를 모두 만드는 과정은 아직 익숙하지 않다.
A → B
A → C
B → A
B → C
C → A
C → B

작은 `k` 값으로 재귀 호출 순서를 직접 적어볼 필요가 있다.

---

### 2. 감염 상태 복사

다음 코드가 리스트를 복사한다는 것은 알고 있다.
next_infected = infected[:]

하지만 DFS 분기마다 왜 별도의 감염 상태가 필요한지 코드 실행 흐름 속에서 아직 완전히 이해하지 못했다.

현재 이해한 내용은 다음과 같다.
A를 선택한 결과와
B를 선택한 결과는
같은 현재 상태에서 독립적으로 시작해야 한다.

따라서 A 선택으로 변경된 감염 상태가 B 선택에 영향을 주면 안 된다.

---

### 3. 다중 시작점 BFS

일반 BFS는 하나의 시작 노드에서 출발한다고 배웠다.

이 문제에서는 현재 감염된 모든 노드가 시작점이 된다.

예를 들어 다음 노드들이 감염되어 있다면:
1, 3, 7

큐의 초기 상태는 다음과 같다.
[1, 3, 7]

아직 다음 내용을 직접 추적해 봐야 한다.

- 1번에서 감염된 노드
- 3번에서 감염된 노드
- 7번에서 감염된 노드
- 이미 감염된 노드가 중복으로 큐에 들어가지 않는 과정

---


## 직접 손으로 확인할 예제

다음 트리를 사용해 감염 과정을 확인한다.
1 ─A─ 2 ─B─ 3 ─A─ 4
        |
        C
        |
        5

초기 감염 노드:
1

### A를 열었을 때
감염 전: {1}
감염 후: {1, 2}

2번과 3번 사이의 파이프는 B이므로 A를 열었을 때 3번까지 갈 수 없다.

### A → B 순서
초기: {1}
A 이후: {1, 2}
B 이후: {1, 2, 3}

### A → C 순서
초기: {1}
A 이후: {1, 2}
C 이후: {1, 2, 5}

### A → B → A 순서
초기: {1}
A 이후: {1, 2}
B 이후: {1, 2, 3}
A 이후: {1, 2, 3, 4}

이 예제를 통해 같은 A 타입이라도 중간에 B를 연 후 다시 사용하면 새로운 감염이 발생할 수 있다는 것을 확인할 수 있다.

---


## 코드별 확인 사항

### 그래프 생성
graph = [[] for _ in range(n + 1)]

노드 번호가 1부터 시작하기 때문에 `n + 1` 크기로 생성한다.
graph[x].append((y, pipe_type))
graph[y].append((x, pipe_type))

파이프는 양방향이므로 양쪽 노드에 모두 연결 정보를 저장한다.

이 부분은 이해했다.

---

### 초기 감염 상태

initial_infected = [False] * (n + 1)
initial_infected[infection] = True

감염 여부를 불리언 리스트로 관리한다.

이 부분은 이해했다.

---

### BFS 시작점 생성

for node in range(1, n + 1):
    if next_infected[node]:
        queue.append(node)

현재 감염된 모든 노드를 큐에 넣는다.

이 부분은 개념적으로 이해했지만, 시간복잡도와 실제 큐의 변화는 다시 확인해야 한다.

---

### 선택한 타입만 통과

if pipe_type != selected_type:
    continue

현재 A를 열었다면 B와 C 간선은 무시한다.

이 부분은 이해했다.

---

### 이미 감염된 노드 제외

if next_infected[next_node]:
    continue

감염 여부가 BFS의 방문 처리 역할도 한다.

양방향으로 저장된 간선을 다시 되돌아가는 것을 막는다.

이 부분은 이해했다.

---

### DFS 종료 조건

if infected_count == n:
    return

모든 노드가 감염되었다면 더 좋은 결과가 없으므로 종료한다.

if depth == k:
    return

최대 행동 횟수만큼 파이프를 열었으므로 종료한다.

이 부분은 이해했다.

---

### 같은 타입 연속 선택 제외

if selected_type == last_type:
    continue

A를 열어 현재 도달 가능한 A 영역을 모두 감염시킨 직후 다시 A를 열어도 새로운 감염은 없다.

다만 `A → B → A`는 가능하므로, A 타입 자체를 한 번만 사용할 수 있는 것은 아니다.

이 부분은 이해했다.
